# Chapter Three: Methodology, System Analysis and Design

## 3.1 Introduction
This chapter explains the methods used to gather requirements, analyze the existing process, and design the Seminary Management and Results System.

## 3.2 Research Design
The study adopts a practical systems development approach combining requirement gathering, analysis, design, implementation, and testing.

## 3.3 Data Collection Methods
Possible data collection methods for the study include:

- Interviews with administrators, lecturers, finance staff, and students
- Observation of record-handling procedures
- Document review of result sheets, fee records, and registration forms

## 3.4 Analysis of the Existing System
The existing setup is often manual or partly computerized, leading to:

- Delays in result processing
- Difficulty retrieving student records
- Repetition and inconsistency of data
- Limited coordination across departments
- Slow transcript preparation
- Weak fee tracking and reporting

## 3.5 Proposed System
The proposed system is SMNS, a web-based platform that centralizes academic and finance operations. It supports user authentication, student management, course registration, result management, transcript generation, payment tracking, and notification services.

## 3.6 Functional Requirements
The system should be able to:

- Manage user accounts by role
- Register and manage students
- Manage courses, semesters, and academic years
- Support course registration workflows
- Capture and publish results
- Compute GPA and transcript data
- Track invoices, payments, and balances
- Generate reports and notifications

## 3.7 Non-Functional Requirements
- Security
- Accuracy
- Usability
- Reliability
- Maintainability
- Performance

## 3.8 System Users
- Administrator
- Student
- Lecturer
- Finance Staff

## 3.9 System Design
The design section should include:

- Use case diagram
- Data flow diagrams
- Entity relationship diagram
- Database schema
- Module interaction overview
- User interface structure

## 3.10 System Architecture
SMNS uses a web-based architecture with:

- Presentation layer for user interfaces
- Application logic layer for workflows and business rules
- Database layer for persistent data storage

## 3.11 Database Design
The system database includes entities such as:

- Users
- Students
- Programs
- Courses
- Semesters
- Course registrations
- Results
- Student GPAs
- Invoices
- Payments
- Student balances

## 3.12 Development Tools and Technologies
Based on the system repository, the project uses:

- PHP for server-side logic
- HTML, CSS, and JavaScript for user interfaces
- MySQL or compatible relational database concepts for data storage
- Draw.io and markdown-based documentation for diagrams and system documentation

## 3.13 Summary of the Chapter
This chapter has presented the methods used to study the problem and the design of the proposed SMNS solution.
